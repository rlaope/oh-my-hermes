Platform convention

Pick a target to see the convention note this brief records.

Platform convention
Native iOS / iPadOS. System controls, semantic adaptive colors, text styles with Dynamic Type, safe areas, VoiceOver — built with the current SDK, not recreated in CSS.
Native macOS. AppKit/SwiftUI system styles, menus, full keyboard access, adaptive layout. macOS has no Dynamic Type; it uses system styles and app text scaling.
Apple-inspired web — this page. System-font fallback stack, semantic HTML, visible focus, zoom and reflow, reduced motion and transparency honored, opaque fallback for every blur. Inspiration, not native equivalence: no SwiftUI, no real Liquid Glass.

Source-backed review

Three sample findings in apple_design_finding/v1 shape, written against the fictional Aurora mock. Sample data — no compliance score is claimed.

High

Content cards rendered as glass

Evidence
Supplied sample mock, overview cards (observation)
Impact
Text legibility varies with whatever scrolls beneath the card
Source
HIG Materials; Adopting Liquid Glass — glass belongs to the control and navigation layer
Fix
Keep content cards opaque; reserve translucency for the toolbar and sidebar
Owner
frontend
Missing check
Rendered captures over light and dark content → visual-qa
Review note

Apple's transient interactive-control exception does not extend to persistent content cards. The 35% dimming example in Materials is conditional guidance for bright content behind glass, not a universal CSS opacity token — so the fix is material choice, not a dimming overlay.

Medium

macOS point sizes reused as CSS pixels

Evidence
Mock stylesheet copies a native point ramp verbatim (observation)
Impact
Small text under browser zoom; layout clips instead of reflowing
Source
HIG Typography — platform-specific; points do not equal CSS pixels
Fix
Rem-based scale with reflow, as in this page's specimen ramp
Owner
frontend
Missing check
200% zoom reflow observation → accessibility-audit
Review note

Dynamic Type is an iOS/iPadOS API and macOS explicitly does not support it; the web analogue is browser zoom and text settings. Claiming a CSS scale "implements Dynamic Type" would overstate the guidance — the finding asks only for zoomable, reflowing units.

Low

Sidebar selection shown by color alone

Evidence
Selected row differs only in tint (observation); users may miss it (hypothesis)
Impact
Selection state can disappear for low-vision and color-blind users
Source
HIG Accessibility; WCAG 1.4.1 Use of Color (web applicability)
Fix
Pair the tint with weight and a leading indicator bar — as this page's sidebar does
Owner
frontend
Missing check
Assistive-technology pass → accessibility-audit
Review note

Apple guidance and WCAG are named separately on purpose: HIG covers Apple-platform expectations, WCAG covers web conformance. Neither is claimed as a PASS here — the check stays open until the accessibility lane records observed evidence.
