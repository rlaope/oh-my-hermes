## Structure and rules

```
<project>/reel/
  index.html    color and typeface tokens (:root), CSS shared by scenes
  engine.js     the engine (do not edit -- new_project.py overwrites it with the latest version)
  fx.js         global layers (grain, HUD, subtitles, flashes, etc.)
  timeline.js   generated by timeline.py (window.TL: cues, narration word times, music hits)
  scenes.js     scene code -- write only here (with many sections, split into scenes_s01.js ... and add script tags to index.html)
  _example_scenes.js  API usage examples (not loaded). Do not use it as the starting point for the visuals
  lib/          keep external scripts such as WebGL libraries here as files (do not rely on the network during a render)
  fonts/        filled by new_project.py
```

The server root is the project folder. Load images by relative path, such as `../assets/img/x.jpg`.

**Rules** -- The renderer jumps straight to arbitrary times, several workers split the timeline into ranges and draw them, and for motion blur it also captures fractional times between frames. Therefore:

1. The result of `render(lt)` must depend only on time. Do not accumulate values computed in a previous frame.
2. Do not use `Math.random()`, `Date.now()`, `performance.now()`, CSS `transition`/`animation`/`@keyframes`, or `requestAnimationFrame` loops. For randomness use `rand(i, salt)`; for jitter use `noise(t, seed)`. Calculations that need accumulation (physics simulations) are computed ahead of time in setup (see "Precomputed simulations" below).
3. Build the DOM in `setup` and only change styles in `render`. Do not create or remove elements in `render`.
4. Use cues instead of numbers for times: `cue('name')`, `cue('line.n03')`, `cue('music.hit2')`. Even if the narration is regenerated, the visuals follow it.
5. Finish exits 0.1 seconds before the scene ends. This is the most common cause of blank frames and ghosting at scene boundaries.

## API summary

```js
const { ease, prog, win, kf, spring, clamp, lerp, map, rand, noise, split, stagger, count, scramble, shake, pulse, level, inout, charTimes, sayChars, bar, beat, css, h, s, cue } = REEL;
REEL.config({ duration: 60, fps: 30, width: 1920, height: 1080, audio: '../audio/mix.wav' }); // audio is for preview only
REEL.scene({ id: 'intro', start: 0, end: cue('line.n03') - 0.3,
  setup(el) { /* build the DOM, SVG, canvas. Store them on this */ },
  render(lt, ctx) { /* lt = time within the scene. ctx = { t, dur, p } */ } });
REEL.img(src)        // preload an image (rendering waits until it is ready) → HTMLImageElement
REEL.TL              // timeline.js: { cues, vo:[{id,text,sub,start,end,words:[[word,start,end]]}], music:{bpm,beats,downbeats,hits} }
```

| Function | Description |
| --- | --- |
| `prog(t, start, dur, e=ease.snap)` | 0->1 over dur, starting at start |
| `win(t, a, b, inDur, outDur)` | 0->1->0, entering at a and leaving at b |
| `kf(t, [[t0,v0],[t1,v1,ease],…])` | Keyframe interpolation |
| `spring(t, t0, f=2.2, z=0.42)` | Damped spring 0->1 (slight overshoot) |
| `split(el, 'char'|'word', {mask})` | Array of character or word spans. Hangul is split by syllable |
| `stagger(t, start, each, dur, i, e)` | Delayed progress of the i-th element |
| `count(p, to, {decimals, from})` | Number string with thousands-separator commas |
| `scramble(final, p, t, seed)` | Resolves from random characters into the final string (Hangul into Hangul) |
| `shake(t, [[t0, amp, decay]])` | {x, y, r} shake |
| `pulse(t, [t0, …], decay)` | Decays from 1 at each hit |
| `inout(el, t, a, b, o)` | Enters at a from a lowered, blurred, enlarged state, and at b exits by being pushed upward while shrinking and blurring. Use this for exits instead of a fade |
| `charTimes(id, sub)`, `sayChars(spans, t, times)` | Per-character narration times; raises the characters one at a time in step with those times |
| `bar(n, frac)`, `beat(n)` | Time of the n-th bar or beat (1-based, same as the cue `bar1`) |
| `level(t, src)` | Loudness 0-1. Without src, the narration at that time; with a line id, that line; with `'music'`, the music energy (a curve made by `timeline.py`) |
| `ease.*` | linear, in/out/inOut Quad/Cubic/Quart/Expo, outQuint, outBack, outElastic, inOutSine, **snap** (entrance), **swift** (in-out), **exit** (exit), **pop** (chips) |

## Order for writing scenes

1. One `REEL.scene` per storyboard scene. Set the start and end with cues.
2. For each section, build a representative frame first and look at the still sheet (style frames, SKILL.md step 7). Once the sections look like different pieces of work and each frame is good enough to serve as a poster, build the rest.
3. Each time you write a scene, pull stills at that scene's start+0.5 s, cue+0.4 s, and end-0.6 s, and look at them.
4. If global layers (camera, flashes, subtitles, etc.) are needed, attach them last.

## Technique code

The code below consists of snippets to drop into `setup`/`render` as they are. Values assume 1920x1080.

### Text: an entrance rising inside a mask

```js
setup(el) {
  this.t1 = h('div', 'center display', el, '무대가 된다.'); css(this.t1, { top: '440px', fontSize: '200px' });
  this.c1 = split(this.t1, 'char', { mask: true });
},
render(lt) {
  const out = prog(lt, 3.2, 0.35, ease.exit);
  this.c1.forEach((c, i) => {
    const p = stagger(lt, 0.2, 0.04, 0.6, i);
    css(c, { transform: `translateY(${(1 - p) * 135 - out * 135}%)`, opacity: p > 0 ? 1 : 0, filter: `blur(${(1 - p) * 8}px)` });
  });
}
```

Because of the margin under the mask (.18em), at 110% the tops of the characters show through like a dash. Push them down to 135% and keep opacity at 0 before the entrance.

### Canvas: particles gathering into text

The calculation is in the setup and render code of the end card in `reel/_example_scenes.js`. Do not copy its colors, typefaces, or composition. The essentials are as follows.

1. In setup, draw the text on an offscreen canvas (the fonts are already loaded).
2. Sample the pixels that have alpha at 5px intervals to make target points.
3. For each particle, set the start point and delay with `rand`.
4. In render, compute the position with `lerp(start, target, ease(progress))`. Do not use the previous position.
5. Use `globalCompositeOperation = 'lighter'` so overlapping areas get brighter.

### Canvas: deterministic flow and data rain

Always compute particle positions as `f(i, t)`. For example, dots flowing across the screen: `x = (rand(i,1)*W + t*speed_i) % W`, `y = rand(i,2)*H + noise(t*0.3, i)*20`. Clear the canvas and redraw it every frame. If you need trails, draw several past times (t-0.03, t-0.06...) with the same formula.

### Transitions: color-field wipe

### Transitions: push

For a transition that pushes the whole next scene up from below, **do not give the background to the scene `section` (el); give it to the moving inner root.** If the section has the background, it covers the previous scene while it slides in, and 2-3 frames go blank.

```js
setup(el) { this.root = h('div', 'full', el); css(this.root, { background: 'var(--bg)' }); /* content goes inside this.root */ },
render(lt) { css(this.root, { transform: `translateY(${(1 - prog(lt, 0, 0.35, ease.swift)) * 100}%)` }); }
```

### Transitions: zoom through

```js
const z = prog(lt, endAt - 0.3, 0.3, ease.inExpo);        // last 0.3 s of the scene
css(this.root, { transform: `scale(${1 + z * 8})`, transformOrigin: '975px 548px', filter: `blur(${z * 6}px)` });
// a short FX.flash 0.1 at the start of the next scene
```

### Music sync: reacting to beats and hits

```js
const hits = REEL.TL.music?.hits || [];
const b = pulse(t, hits, 0.25);                           // decays from 1 at each hit
css(this.glow, { opacity: 0.3 + 0.5 * b, transform: `scale(${1 + 0.04 * b})` });
```

Align scene boundaries to the nearest value among the `downbeats`. When the cuts land on the beat, the edit comes alive.

### Reacting to loudness: waveforms and a border that glows while speaking

`timeline.py` puts loudness curves into `timeline.js`: at 20ms intervals for each narration line, and at 50ms intervals for the music. If you change the narration or the music, you only need to rerun `timeline.py`.

```js
// Voice introduction: while speaking, the bar waveform follows the actual voice
bars.forEach((b, i) => {
  const v = level(t - (bars.length - 1 - i) * 0.03);          // each bar takes a value 30ms further back → a flowing waveform
  b.style.transform = `scaleY(${0.06 + 0.94 * v})`;
});
css(this.frame, { boxShadow: `0 0 ${40 * level(t, 'n12')}px var(--accent)` });  // reacts only to a specific line
css(this.bg, { opacity: 0.35 + 0.4 * level(t, 'music') });  // background brightness follows the music energy
```

Use it as is for large motions such as bar height, and scale it down to 0.3-0.5x for conspicuous values such as brightness and size. The value changes every frame, so if the flicker is severe, average it, as in `(level(t) + level(t - 0.04) + level(t - 0.08)) / 3`.

## WebGL: shaders and 3D

In the renderer (headless Chrome), WebGL2 shaders and three.js (r160 `build/three.min.js`) scenes render, a different frame comes out for each time, and `--sub 4` motion blur works too (confirmed 2026-10). The rules are the same as for other scenes: drawing happens only inside `render(lt)`, and only as a function of time.

- Create the context with `preserveDrawingBuffer: true`. This keeps frames from coming out black because the buffer is empty at capture time.
- Fix the canvas size at `REEL.W × REEL.H` pixels and set the CSS size to match. The scene coordinates do not change even in a `--scale 0.5` draft.
- Put the licensed library files you were given (or that exist in the approved dependency root) into `reel/lib/` and load them in `index.html`, before `engine.js`, with `<script src="lib/three.min.js"></script>`. Do not rely on a CDN during a render.
- For the three.js animation mixer, set the time with `mixer.setTime(lt)`. Do not use `clock.getDelta()`.
- To render Hangul in 3D, draw the text on a 2D canvas and attach it as a `THREE.CanvasTexture`, or lift points sampled from the text pixels (T04) into 3D coordinates.

Shader (a fragment shader on a single full-screen quad):

```js
setup(el) {
  const c = h('canvas', '', el); c.width = REEL.W; c.height = REEL.H;
  css(c, { position: 'absolute', left: 0, top: 0, width: REEL.W + 'px', height: REEL.H + 'px' });
  const gl = this.gl = c.getContext('webgl2', { preserveDrawingBuffer: true, antialias: true });
  const sh = (type, src) => { const o = gl.createShader(type); gl.shaderSource(o, src); gl.compileShader(o);
    if (!gl.getShaderParameter(o, gl.COMPILE_STATUS)) throw new Error(gl.getShaderInfoLog(o)); return o; };
  const pr = this.pr = gl.createProgram();
  gl.attachShader(pr, sh(gl.VERTEX_SHADER, `#version 300 es
in vec2 p; void main(){ gl_Position = vec4(p, 0., 1.); }`));
  gl.attachShader(pr, sh(gl.FRAGMENT_SHADER, `#version 300 es
precision highp float; uniform float t; uniform vec2 r; out vec4 o;
void main(){ vec2 u = (gl_FragCoord.xy - .5 * r) / r.y;
  float d = length(u) - .3 - .05 * sin(10. * atan(u.y, u.x) + t * 6.);
  o = vec4(mix(vec3(1., .3, .1), vec3(.05, .1, .3), smoothstep(0., .01, d)), 1.); }`));
  gl.linkProgram(pr);
  gl.bindBuffer(gl.ARRAY_BUFFER, gl.createBuffer());
  gl.bufferData(gl.ARRAY_BUFFER, new Float32Array([-1, -1, 1, -1, -1, 1, 1, 1]), gl.STATIC_DRAW);
  const loc = gl.getAttribLocation(pr, 'p'); gl.enableVertexAttribArray(loc); gl.vertexAttribPointer(loc, 2, gl.FLOAT, false, 0, 0);
},
render(lt) {
  const gl = this.gl; gl.viewport(0, 0, REEL.W, REEL.H); gl.useProgram(this.pr);
  gl.uniform1f(gl.getUniformLocation(this.pr, 't'), lt);
  gl.uniform2f(gl.getUniformLocation(this.pr, 'r'), REEL.W, REEL.H);
  gl.drawArrays(gl.TRIANGLE_STRIP, 0, 4);
}
```

three.js:

```js
setup(el) {
  const r = this.r = new THREE.WebGLRenderer({ antialias: true, preserveDrawingBuffer: true });
  r.setPixelRatio(1); r.setSize(REEL.W, REEL.H, false); el.appendChild(r.domElement);
  css(r.domElement, { position: 'absolute', left: 0, top: 0, width: REEL.W + 'px', height: REEL.H + 'px' });
  this.scene = new THREE.Scene();
  this.cam = new THREE.PerspectiveCamera(35, REEL.W / REEL.H, 0.1, 100); this.cam.position.set(0, 0, 8);
  this.m = new THREE.Mesh(new THREE.TorusKnotGeometry(1.4, 0.45, 256, 32),
    new THREE.MeshStandardMaterial({ color: 0xff5a1f, metalness: 0.6, roughness: 0.25 }));
  const key = new THREE.DirectionalLight(0xffffff, 3); key.position.set(3, 4, 5);
  this.scene.add(this.m, key, new THREE.AmbientLight(0x404060, 1.2));
},
render(lt) { this.m.rotation.set(lt * 0.8, lt * 1.3, 0); this.r.render(this.scene, this.cam); }
```

Note: you do not need to draw while the scene is off (`display:none`). Make randomness in a shader with a deterministic hash such as `fract(sin(dot(...)))`. A large shader can take tens of ms per frame, so look at the draft render time and estimate the final render time from it.

## Precomputed simulations

For motion that needs the previous state, such as cloth flapping or fragments colliding and piling up, compute it in setup all the way to the end at a fixed interval (1/fps or finer), store it in an array, and in render read it by time and interpolate. Set the randomness of the initial values with `rand(i, salt)`. This way the same image comes out no matter which time a render worker starts drawing from.

```js
setup() {
  const N = 400, steps = Math.ceil((this._e - this._s) * 120);          // scene length (s) × 120 steps. The engine fills _s and _e before setup
  const S = this.states = new Float32Array((steps + 1) * N * 2);
  let x = Array.from({ length: N }, (_, i) => rand(i, 1) * REEL.W), y = Array.from({ length: N }, (_, i) => -rand(i, 2) * 600);
  let vx = x.map((_, i) => (rand(i, 3) - 0.5) * 200), vy = x.map(() => 0);
  for (let k = 0; k <= steps; k++) {
    for (let i = 0; i < N; i++) {
      S[(k * N + i) * 2] = x[i]; S[(k * N + i) * 2 + 1] = y[i];
      vy[i] += 2400 / 120; x[i] += vx[i] / 120; y[i] += vy[i] / 120;
      if (y[i] > 900) { y[i] = 900; vy[i] *= -0.45; vx[i] *= 0.8; }  // bounces off the floor
    }
  }
  this.N = N; this.steps = steps;
},
render(lt) {
  const f = Math.min(this.steps, lt * 120), k = Math.floor(f), a = f - k, k2 = Math.min(this.steps, k + 1), S = this.states;
  for (let i = 0; i < this.N; i++) {
    const px = S[(k * this.N + i) * 2] * (1 - a) + S[(k2 * this.N + i) * 2] * a;
    const py = S[(k * this.N + i) * 2 + 1] * (1 - a) + S[(k2 * this.N + i) * 2 + 1] * a;
    // draw with px, py
  }
}
```

`this._s` and `this._e` are the scene's start and end times (in seconds), which the engine fills in before it calls setup. If the number of steps times the number of elements goes past tens of millions, setup takes a long time, so reduce the element count or the interval.

## Global layers (fx.js)

All of these are optional. Call only what the concept needs, at the end of `scenes.js`. The call order is the top-to-bottom order. Do not attach letterbox, grain, vignette, and HUD all together out of habit (the "obvious screens" in `craft-design.md`).

```js
FX.camera({ shakes: [[cue('name'), 14, 0.4]], drift: 0.6 });          // shake and drift for the whole scene
FX.flash([[cue('name'), 0.2, 0.12]]);                                  // [time, length, intensity (≤0.15), color]
FX.leak([[cue('scene.s02'), 1.4, 'rgba(255,170,70,.9)', 0.7]]);
FX.letterbox(t => 1 - prog(t, cue('name') - 0.1, 0.5, ease.swift) + prog(t, 57, 0.5, ease.swift));  // 1=closed
FX.vignette({ strength: 0.6 });
FX.grain({ opacity: 0.09 });
FX.hud({ left: '<label>', chapters: [[0, '<section name>'], ['scene.s01', '<section name>']], from: 3, to: 57 });
FX.subtitles({ size: 40 });                                            // burns in the sub of TL.vo. "nosub" lines are left out of the burn-in only (they stay in the SRT; to leave them out of the SRT use "nosrt")
// For vertical (9:16) video, the HUD and subtitles automatically avoid the app UI areas (top 250px, bottom 420px)
```

## Using the renderer

```bash
node $S/render.mjs --dir reel --serve                                  # preview URL (you may also give it to the user)
node $S/render.mjs --dir reel --stills 1.2,4.5,9 --outdir qa/stills    # stills at the given times
node $S/render.mjs --dir reel --every 0.5 --from 8 --to 16 --outdir qa/stills_s01
node $S/render.mjs --dir reel --out out/draft.mp4 --scale 0.5          # draft
node $S/render.mjs --dir reel --out out/video.mp4 --sub 4 --format png # final (motion blur)
```

- The first line of the log lists the loaded fonts. If the typeface you want is not there, check `fonts/fonts.css`.
- Exit code 2 is a page error. Fix the `[pageerror]` in the log.
- The render log shows only `console.error` and `console.warn` messages that start with `[REEL]`. Leave debug values from scene code with `console.warn('[REEL] …')`.
- The final render is saved in chunks (2 seconds each), so if it is interrupted, running the same command again resumes the render. If you change settings, it renders again from the beginning.
- If another render is running on the same computer, it becomes more than 10x slower. Cut it down with `--workers 2`.

## Splitting the work

For a showreel with many sections or a video longer than 3 minutes, split the code per section (or chapter) into `scenes_s01.js`, `scenes_s02.js` and add script tags to `index.html`. Keep shared helpers in `scenes_common.js`. For a showreel whose art direction differs per section, you can hand the sections to subagents, one each, and build them concurrently. The main agent checks that the concept holds, and takes the transitions between sections and the overall critique.

When handing a section to a subagent, put the following contract in the prompt.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| Elements of another scene show through | The engine turns scenes off with `display:none`. If the element was created outside the scene (`REEL.top`, etc.), hide it yourself |
| Text is visible on the first frame and then disappears | Check that the pre-entrance state (opacity 0, translate) is applied in `render` even when lt=0 |
| Text width or position is off | Measuring in `setup` works (it runs after the fonts load). Do not measure during the render |
| The image jumps at worker boundaries | There is accumulated state. Rewrite render as a function of time |
| Rendering is slow | Reduce full-screen `filter: blur()` and large `box-shadow`. Keep canvas particles within 2,000-10,000, and create gradient objects in setup |
| Blank frames at scene boundaries | Make something, anything, move in the next scene within 6-20 frames of its start. Finish exits 0.1 s before the cut |
| Cropping at 9:16 | Change width/height in `REEL.config` and write coordinates as ratios of `REEL.W`/`REEL.H` |
