What you get

  • The right model for every lane.

    Each lane is tagged with a work category: ultrabrain, deep, visual-engineering, quick and more. The category picks that lane's model chain and reasoning effort, and you can edit every chain. When a provider rejects a model, the chain moves to the next one instead of silently downgrading.

    See which model runs each lane

  • /dag-ulw graph runs.

    Your goal becomes a graph of small nodes, and the ready ones run in parallel. Each node runs on its category's model and effort; nodes running at once never share a write scope. A separate node checks the goal, and failed nodes are repaired before the report.

  • Expert skills on demand.

    A hundred-plus omh-* specialists: frontend, backend, Rust, security review, verification gates. You never call them; the router loads the right ones into the run as tool calls.

  • Long-term memory you can trust.

    Nothing is remembered silently: each candidate is kept, refused or deferred with a written reason. The next session gets a recall pack ranked for its task and cut to a token budget. Hermes' own memory is never read or patched.

  • OMH Native.

    Bare omh opens OMH's own TUI on Hermes' gateway; switch its launch look with /theme. /dag-ulw prints the box graph, then a live lane tree with each lane's model, effort and tokens. Steer or interrupt an agent from the agent list, run a ! shell line, and rewind with Esc Esc.

  • Evidence before "done".

    Every status names its stage and how sure OMH is about it. A run counts as verified only when a test, review or CI gate actually passed.

    Plan · not run
    A prompt or plan is ready. Nothing has run yet.
    Code · running
    An executor is running now, and OMH is watching it.
    Code · reported done
    The executor said it finished. Nobody checked the result.
    Test · verified
    A test, review, or CI gate actually passed.

Install once. Set up once.

Pick one way to install the command, then run setup. Doctor is a separate check you can run any time.

Homebrew, Bun, and npm package-manager installs are public as of v1.0.6.

  1. Install the command

    macOS · Linux 
    curl -fsSL https://raw.githubusercontent.com/rlaope/oh-my-hermes/main/install.sh | sh
    Windows · PowerShell 5.1+ 
    irm https://raw.githubusercontent.com/rlaope/oh-my-hermes/main/install.ps1 | iex
    Homebrew 
    brew install rlaope/tap/omh
    Bun 
    bun install -g oh-my-hermes
    npm 
    npm install -g oh-my-hermes

    Use the macOS · Linux or Windows installer; it finds Python 3.11+ itself. Homebrew, Bun, and npm install the published release: Bun and npm also need Node 18+ and Python 3.11+ on PATH, and Homebrew brings its own Python.

  2. Set it up

    omh 
    omh setup

    Run it after any of the installs above.

  3. Verify or troubleshoot

    omh 
    omh doctor

    Refresh later with omh update: it upgrades the command through the installer that owns it, then refreshes the managed skills, the plugin bundle, and the Hermes registration.

Flagship workflows

The ulw-* family.

Ten long-horizon lanes.

  1. ulw-context Terminology alignment

    Context

    Aligns the words a repository uses before plans and handoffs.

    Say ulw-context review project terms

  2. ulw-interview Clarification

    Deep Interview

    One question at a time until the brief is clear.

    Say deep-interview clarify

  3. ulw-research Decision grounding

    Research

    Reference implementations, live web evidence, verified claims.

    Say web research source-backed research

  4. ulw-plan Reviewed plan

    Ralplan

    Consensus planning with review gates.

    Say ralplan consensus plan

  5. ulw-work Parallel delivery

    Ultrawork

    Splits an accepted plan into disjoint lanes.

    Say ultrawork parallel work

  6. dag-ulw Graph run

    DAG ULW

    Plans a graph of small nodes, runs them in parallel, verifies and repairs.

    Say dag ulw /dag-ulw

  7. ulw-maestro External handoff

    Maestro

    Runs the work on Claude Code or Codex, spawned live with a steerable session.

    Say ulw-maestro coding handoff

  8. ulw-loop Goal loop

    Loop

    Interview → plan → research → build → review.

    Say loop long horizon goal

  9. ulw-qa Adversarial QA

    UltraQA

    Hostile scenarios, end-to-end runs, release QA.

    Say ultraqa release qa

  10. ulw-perf Measured optimization

    Ultraperf

    Finds where the system is actually slow, leaking, or expensive.

    Say ultraperf find the bottleneck
